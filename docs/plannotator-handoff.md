# Plannotator handoff

Read this reference after the calling skill's interview is complete. Its intake,
plan fields, exceptions, and completion rules still apply.

1. **Enable review.** In interactive Pi, use Plannotator planning mode. If it is off, ask the user to run `/plannotator-plan-mode`. If the command or `plannotator_submit_plan` is missing, ask them to run `pi install npm:@plannotator/pi-extension`, then `/reload` or restart Pi. Wait until the mode and tool are available; other plan-mode extensions do not substitute. Outside Pi, ask for an available Plannotator integration; do not invent a tool or substitute a text brief. Stop before submission in noninteractive mode or when browser review is unavailable: the extension can auto-approve without user review.
2. **Write the plan.** For applicable coding work, load `${AGENTIC_HOME:-$HOME/.agentic}/skills/pattern-gate/SKILL.md` before drafting. Save one self-contained Markdown plan in the working directory, at the project's existing plan location or `plans/<short-name>.md`. Reuse that path for revisions without overwriting another plan. Include the caller's required fields, existing code to reuse, an implementation checklist (`- [ ]`), and concrete verification commands or manual checks. Resolve blocking questions; label nonblocking assumptions.
3. **Request joint approval.** Applicable coding plans include a **Pattern list** with each pattern's name, where, and why; resolve open pattern choices before review. State that approval covers the plan and pattern list together and implementation waits for it. Explain that Plannotator's default `automatic` execution mode starts implementation after approval; respect an existing `external` configuration without changing it. Approval happens in Plannotator, with no additional chat approval, compaction, or **ready** reply required. Put any caller-required completion suggestions at the end of the plan before submission, since the submit tool ends the turn.
4. **Submit and stop.** Finish writing before calling `plannotator_submit_plan({"filePath":"plans/<short-name>.md"})` with the actual relative path. Call it separately from writes or edits. The tool returns when review opens, not when approval arrives. End the turn and wait for the later decision message; pending review is not approval. If submission fails, report the error without claiming review or approval.
5. **Handle the decision.** On denial or requested changes, read the plan, make targeted edits, and resubmit the same file. Reopen the interview one question at a time if requirements change. On approval with notes, incorporate them during execution; do not treat an approved plan as denied. Plannotator's configured execution workflow owns implementation after approval. Preserve the approved scope and pattern list through later compaction.
